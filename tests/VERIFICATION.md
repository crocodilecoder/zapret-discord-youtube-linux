# Заметки по проверке порта

Писалось и проверялось в контейнере debian 12 без CAP_NET_ADMIN и без
netfilter-модулей в ядре, то есть живой перехват трафика там физически
не поднимается — всё, что касается ядра, проверялось на моках и dry-run.
На живой машине дополнительно прогнать то, что написано в конце.

## Что гоняется автоматически (tests/run_all.sh)

- test_01: shellcheck и bash -n по всем скриптам. Без предупреждений.
- test_02: самое главное. Аргументы каждого general_*.sh сравниваются
  с аргументами winws.exe из соответствующего bat-ника (эталонные копии лежат
  в tools/win_bats). Совпадение побайтовое, при выключенном и включённом
  игровом фильтре. 44 сравнения, все идентичны.
- test_03: настоящий nfqws --dry-run кушает аргументы всех 22 стратегий,
  число профилей совпадает с числом --new+1, все hostlist/ipset/фейки
  загружаются.
- test_04: юнит-тесты common.sh: разбор game_filter.enabled (режимы, битые
  диапазоны), user-списки, статусы ipset, списки портов, порядок стратегий
  (совпадает с нумерацией меню в винде).
- test_05: правила фаервола на моке iptables: цепочка, метка десинка,
  nfqueue с queue-bypass, ipv6, режим шлюза, stop, nft-бэкенд, отказ без рута.
  Сгенерированный nft-скрипт дополнительно кушает настоящий nft -c.
- test_06: жизненный цикл службы на моках systemctl и nfqws: install, status,
  stop, start, restart, remove, вариант без systemd, отказ второго экземпляра,
  меню.
- test_07: утилиты меню: цикл ipset-switch с бэкапом, game-filter cli,
  подмена фейков по sha256, update-ipset/update-hosts/check-updates
  на file://-фикстурах, диагностика.
- test_08: e2e: test_zapret.sh гоняет две стратегии против локального
  http-сервера, пишет отчёт в utils/test results/, возвращает обратно
  заранее запущенный nfqws.

Итого 8 наборов, около 280 проверок, всё зелёное.

По ходу вылезли и исправлены три своих бага: grep -q active матчил
"inactive" (поставил -x), зомби-процессы считались живыми экземплярами nfqws
(проверка по /proc/pid/stat), и iptables multiport не понимает диапазоны
через дефис (теперь конвертятся в двоеточие, на живой kali это и ломало
запуск).

## Что проверить на живой машине

```bash
sudo ./install.sh
sudo ./firewall.sh start
iptables -t mangle -S | grep ZAPRET_DY      # правила на месте
sudo ./general.sh                            # в соседнем терминале curl'ом
cat /proc/net/netfilter/nfnetlink_queue      # очередь 200 живая, dropped ~0
sudo ./test_zapret.sh                        # полный прогон с аналитикой
sudo ./service.sh install general.sh         # служба
systemctl status zapret
```

Критерий простой: там, где без него discord/youtube отваливался,
с ним всё открывается, в отчёте тестера HTTP:OK и TLS:OK у выбранной
стратегии.

## Известные грабли

- нужен bash, на чистом sh не поедет (массивы, [[ ]]);
- если в системе свой nft-конфигуратор, проще включить ZAPRET_FW=nft;
- shipped-бинарник собран на debian 12 (glibc 2.36), на более старых
  системах пересобрать: sudo FORCE_REBUILD=1 ./install.sh;
- nfqws после старта сбрасывает capabilities, и на машинах с home 700
  (kali) списки не читались даже под root: лечится автоматическим
  chmod o+x на каталоги пути (ensure_traverse в common.sh), проверено
  юнит-тестом и воспроизведением на живой kali;
- режим шлюза (ZAPRET_ROUTER=1) упрощён по сравнению с upstream zapret,
  для серьёзного роутера лучше посмотреть их /opt/zapret.
